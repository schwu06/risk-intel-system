# 启动数据库锁修复记录

记录时间：2026-08-07 10:21:40（Asia/Tokyo）

## 故障现象

应用执行启动迁移时，在 `industry_migration._delete_report_from_main()` 删除主库中的旧研报记录，抛出 `sqlite3.OperationalError: database is locked`，导致 FastAPI lifespan 中断、Uvicorn 退出。

日志中的 `GEMINI_API_KEY` 警告与本次启动失败无关；它只表示主体评估无法调用 Gemini 进行结构化分析。

## 根因

`migrate_legacy_data()` 在没有数据需要更新时只执行查询，没有结束 SQLAlchemy 会话的只读事务。紧接着，行业迁移通过另一条原生 `sqlite3` 连接写入同一个主库。旧会话仍占用数据库事务，新的连接因此无法执行删除，形成进程内自锁。

行业迁移自身还把 ORM 实体保留到原生连接删除阶段，没有在切换连接前主动释放查询事务，进一步放大了锁冲突概率。

## 修复方式

- `migrate_legacy_data()` 返回前始终提交并结束当前事务，包括“无需更新”的只读路径。
- 行业迁移开始时结束调用方遗留事务，只读取研报 ID 与行业名称的标量快照。
- 获取快照后关闭 ORM 查询事务，再使用原生 SQLite 连接复制和删除数据。
- 主库删除连接与行业库复制连接增加 30 秒连接超时和 `busy_timeout`，容忍短暂的外部写锁。
- 忽略运行时生成的 `*.sqlite3-shm` / `*.sqlite3-wal`，避免启动后重新污染工作区。
- 保留原有“先复制、后删除”顺序；如果中途重试，目标库使用 `INSERT OR IGNORE` 保持幂等。

本地待迁移的 4 份研报已经完整转移：航空 2 份、航运 1 份、轮胎 1 份。主库中的旧研报数量为 0，各行业库总数仍为 4，没有观察到重复或丢失。
